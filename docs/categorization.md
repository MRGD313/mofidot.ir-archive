# دسته‌بندی آرشیو مفیدات

این سند نحوهٔ ساخت، بازبینی و اجرای دسته‌بندی پست‌های آرشیو را توضیح می‌دهد.

## ۱) چرا Discovery-First؟

دسته‌بندی از فهرست ثابت و از پیش تعیین‌شده شروع نمی‌شود. تاکسونومی باید از دل محتوای واقعی کانال بیرون بیاید، چون موضوعات کانال در طول زمان تغییر می‌کنند و یک فهرست دستی ممکن است بخش‌های مهمی از آرشیو را نادیده بگیرد.

در حالت `--discover`، اسکریپت نمونه‌ای از پست‌ها را می‌خواند و دسته‌های پیشنهادی را همراه با کلیدواژه و توضیح تولید می‌کند. سپس شما فهرست را بازبینی می‌کنید و آن را به `categories.json` تبدیل می‌کنید. به این ترتیب دسته‌ها با زبان و دغدغه‌های واقعی کانال هم‌راستا هستند.

## ۲) جریان کامل کار

### الف) کشف دسته‌ها

با API Key:

```bash
export DEEPSEEK_API_KEY="..."
python scraper/categorize.py --discover --sample 40
```

بدون API Key (توسط OpenCode یا به‌صورت دستی):

```bash
python scraper/categorize.py --discover --from-json discovery.json
```

`discovery.json` باید ساختاری مانند این داشته باشد:

```json
{
  "categories": [
    {
      "name": "فناوری و علم",
      "keywords": ["هوش مصنوعی", "فناوری", "پژوهش"],
      "description": "اخبار فناوری و یافته‌های علمی."
    }
  ]
}
```

برای دیدن جدول بازبینی بدون نوشتن فایل:

```bash
python scraper/categorize.py --discover --from-json discovery.json --dry-run
```

در خروجی، برای هر دسته نام، تعداد کلیدواژه و توضیح نمایش داده می‌شود.

### ب) بازبینی `categories.json`

فایل `src/data/categories.json` فقط `name` و `keywords` را نگه می‌دارد؛ توضیح‌ها فقط برای بازبینی در مرحلهٔ discovery هستند. اگر نام یا کلیدواژه‌ای مناسب نیست، همان‌جا اصلاح کنید.

### ج) دسته‌بندی اولیه

```bash
python scraper/categorize.py --initial
```

این دستور همهٔ پست‌هایی را که `category` آن‌ها `null` است پردازش می‌کند. اگر `DEEPSEEK_API_KEY` وجود داشته باشد و `--auto` را هم اضافه کنید، از LLM استفاده می‌شود؛ در غیر این صورت fallback کلیدواژه‌ای اجرا می‌شود.

برای دیدن نتیجه بدون تغییر فایل‌ها:

```bash
python scraper/categorize.py --initial --dry-run
```

### د) Commit و Push

```bash
git add src/content/posts/ src/data/categories.json
git commit -m "chore: categorize posts"
git push
```

بعد از push، workflow سایت را دوباره می‌سازد و صفحه‌های دسته‌ها را از روی مقادیر `category` در پست‌ها می‌سازد.

## ۳) استفاده از OpenCode بدون API Key

اگر API Key ندارید، می‌توانید از خود OpenCode بخواهید یک فایل `discovery.json` اولیه بسازد:

1. چند پست یا خلاصه‌ای از موضوعات کانال را به OpenCode بدهید.
2. از آن بخواهید ۵ تا ۱۰ دستهٔ فارسی با `name`، `keywords` و `description` پیشنهاد کند.
3. خروجی را در `discovery.json` ذخیره کنید.
4. این دستورها را اجرا کنید:

```bash
python scraper/categorize.py --discover --from-json discovery.json
python scraper/categorize.py --initial
```

در این مسیر هیچ درخواستی به سرویس LLM ارسال نمی‌شود و کل فرایند رایگان است.

## ۴) ویرایش دستی دسته‌ها

فایل `src/data/categories.json` را باز کنید و یک ورودی جدید اضافه کنید:

```json
{
  "name": "ورزش",
  "keywords": ["فوتبال", "والیبال", "تمرین", "مسابقه"]
}
```

نکات:

- `name` باید یکتا و کوتاه باشد.
- `keywords` را با عبارت‌هایی پر کنید که واقعاً در متن پست‌ها دیده می‌شوند.
- کلیدواژه‌های چندکلمه‌ای مجاز هستند.
- بعد از ویرایش، `--initial` یا `--incremental --auto` را اجرا کنید تا پست‌های بدون دسته با فهرست جدید پردازش شوند.

## ۵) دسته‌بندی دوباره از صفر

دو راه وجود دارد:

1. مقدار `category` همهٔ پست‌ها را `null` کنید و بعد `--initial` را اجرا کنید.
2. از `--force` استفاده کنید:

```bash
python scraper/categorize.py --initial --force
```

با `--force` همهٔ پست‌ها دوباره بررسی می‌شوند، حتی آن‌هایی که از قبل دسته دارند. اگر برای پستی هیچ تطابقی پیدا نشود، مقدار آن دوباره `null` می‌شود.

برای اجرای آزمایشی:

```bash
python scraper/categorize.py --initial --force --dry-run
```

## ۶) تخمین هزینه

- **اجرای اولیه:** حدود ۴۰۰ پست در چند batch کوچک به مدل فرستاده می‌شود. با مدل ارزان DeepSeek، هزینه معمولاً چند سنت است و در بیشتر موارد زیر ۰٫۰۵ دلار می‌ماند.
- **اجرای incremental:** فقط پست‌های جدید و بدون دسته فرستاده می‌شوند؛ معمولاً ۰ تا ۲۰ پست در هر اجرا. هزینهٔ آن تقریباً صفر است.
- **بدون API Key:** هزینهٔ LLM صفر است و فقط fallback کلیدواژه‌ای اجرا می‌شود.

## ۷) نکات عملیاتی

- **Idempotency:** در حالت عادی فقط پست‌های `category: null` پردازش می‌شوند. اجرای دوبارهٔ `--incremental` تغییری ایجاد نمی‌کند و همان پست‌ها دوباره نوشته نمی‌شوند.
- **Atomic writes:** هر فایل پست با یک فایل موقت در همان پوشه نوشته و سپس با `os.replace` جایگزین می‌شود. اگر اجرا وسط کار قطع شود، فایل نیمه‌نوشته باقی نمی‌ماند.
- **Guard برای تاکسونومی خالی:** اگر `src/data/categories.json` خالی باشد، دستورهای دسته‌بندی با این پیام خارج می‌شوند:

  ```text
  categories.json is empty. Run --discover first, or add categories manually.
  ```

  در GitHub Actions این خطا با `continue-on-error` مدیریت می‌شود و پست‌ها با `category: null` باقی می‌مانند.
- **Dry-run:** با `--dry-run` هیچ فایل پست یا فایل دسته‌ای نوشته نمی‌شود؛ فقط جدول و خلاصه چاپ می‌شود.
- **CI:** اگر Secret با نام `DEEPSEEK_API_KEY` تنظیم شده باشد، workflow از LLM استفاده می‌کند؛ در غیر این صورت fallback کلیدواژه‌ای اجرا می‌شود.
